# OpenAPI 3.1: спецификация, которую читает человек и инструмент

OpenAPI описывает пути, операции, параметры, тела, ответы и схемы. Это не замена обсуждению, а единый контракт для frontend, backend, QA и генераторов клиентов. Версию спецификации фиксируйте явно.

```yaml
openapi: 3.1.0
paths:
  /appointments:
    post:
      summary: Создать запись
      parameters:
        - in: header
          name: Idempotency-Key
          required: true
          schema: { type: string, minLength: 1 }
      responses:
        '201': { description: Запись создана }
        '409': { description: Слот уже занят }
```

Полный контракт добавит `requestBody`, схему `Appointment`, примеры и общий `Error`. Пример не должен противоречить схеме: если `startsAt` имеет формат `date-time`, не кладите туда «завтра утром».

Проверяйте контракт до реализации: все ли статусы покрыты? Можно ли отличить `400` (некорректный запрос), `401` (не аутентифицирован), `403` (нет права), `404` (нет ресурса) и `409` (конфликт состояния)?
