# Нефункциональные требования и наблюдаемость

NFR полезно, когда оно измеримо и связано с риском. «Система быстрая» нельзя принять; «95% поиска слотов за 500 мс при 100 RPS» — можно. Цифры согласуют с бизнесом и командой, а не копируют из шаблона.

| Область | Пример требования | Как проверить |
| --- | --- | --- |
| Производительность | p95 `GET /slots` ≤ 500 мс | Нагрузочный тест и метрика |
| Доступность | API записи ≥ 99.9% в месяц | SLI/SLO и мониторинг |
| Безопасность | Доступ к записи только владельцу/сотруднику | Авторизационные тесты |
| Аудит | Смена статуса хранит кто/когда/почему | Просмотр audit log |

Наблюдаемость строится на логах, метриках и трассировках. В каждый внешний запрос передавайте correlation/trace ID. Логируйте событие и контекст, но не пароль, токен и лишние персональные данные. Alert должен говорить о пользовательском риске, а не о каждом единичном исключении.
