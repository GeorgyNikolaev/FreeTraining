# Передача управления между графами

Подграф из прошлого урока заканчивался и возвращал управление родителю — туда, откуда его позвали. Но бывает иначе: подграф в процессе работы понимает, что дальше должен работать кто-то другой. Проверка ДЗ обнаружила, что студент вообще не понял тему, — надо не разбирать решение, а объяснять материал.

Это и есть передача управления (handoff).

## `Command(graph=Command.PARENT)`

Узел подграфа может отправить `Command` не в свой граф, а в родительский:

```python
from langgraph.types import Command


def check_criterion(state: HomeworkState) -> Command:
    if state["misunderstood_topic"]:
        return Command(
            update={"answer": "Похоже, стоит вернуться к теории."},
            goto="explain",              # узел РОДИТЕЛЬСКОГО графа
            graph=Command.PARENT,
        )
    ...
```

Проверено на langgraph 1.2.11: подграф действительно завершается, и управление оказывается в узле `explain` родителя, а обновление состояния применяется к родительскому состоянию.

**Важная ловушка.** Аннотировать такой узел `Command[Literal["explain"]]` нельзя: движок примет `explain` за узел подграфа и упадёт ещё при компиляции — «Found edge ending at unknown node `explain`». Оставляйте просто `-> Command`, а видимость связи обеспечивайте комментарием или схемой родителя.

Ещё одно следствие: у такого узла в подграфе не должно быть обычного ребра в `END` — граф завершится через передачу управления.

## Handoff-инструменты

В агентных архитектурах передачу управления чаще оформляют не узлом, а **инструментом**: модель сама решает, что пора звать коллегу.

```python
from langchain.messages import ToolMessage
from langchain.tools import tool
from langgraph.prebuilt import ToolRuntime
from langgraph.types import Command


@tool
def передать_теоретику(причина: str, runtime: ToolRuntime) -> Command:
    """Передать разговор агенту, который объясняет теорию.

    Используй, когда студент не понимает материал, а не ошибается в решении.
    """
    return Command(
        goto="theory_agent",
        graph=Command.PARENT,
        update={
            "messages": [ToolMessage(content=f"Передано теоретику: {причина}",
                                     tool_call_id=runtime.tool_call_id)],
            "handoff_reason": причина,
        },
    )
```

Приём собирает вместе всё из модуля 04: инструмент возвращает `Command`, сам создаёт `ToolMessage` с `tool_call_id` и переходит в другой узел. Модель при этом не знает слова «граф» — она просто вызывает инструмент с понятным названием.

Готовая реализация такого инструмента есть в пакете `langgraph-swarm` (`create_handoff_tool`), если не хочется писать руками.

## Что передавать вместе с управлением

Вопрос, который решает половину проблем мультиагентных систем: **что видит следующий агент**.

| Вариант | Что происходит | Когда годится |
|---|---|---|
| Вся история сообщений | новый агент видит всё, включая чужие вызовы инструментов | короткие диалоги; быстро раздувает контекст |
| Последнее сообщение пользователя | агент начинает почти с нуля | агенты решают независимые задачи |
| Своё поле состояния (`handoff_reason`, выжимка) | передаёте ровно нужное | по умолчанию лучший выбор |

Полная история кажется безопасным вариантом, но именно она превращает мультиагентную систему в дорогую и непредсказуемую: каждый агент платит за контекст всех предыдущих и иногда путается в чужих инструментах.

## Циклы и лимиты

Передача управления замыкается: теоретик решает, что вопрос всё-таки про домашнее задание, и передаёт обратно. Два агента могут перекидываться разговором, пока не кончится лимит шагов.

Лечится тем же, чем цикл в модуле 03: счётчиком в состоянии. Правило «не больше двух передач за запрос, дальше отвечает тот, у кого управление» простое и работает.

## Типичные ошибки

**`Literal`-аннотация у узла с передачей наверх.** Ошибка компиляции о неизвестном узле — и непонятно, при чём тут подграф.

**Handoff без `ToolMessage`.** Знакомая по модулю 04 поломка протокола: вызов инструмента остался без ответа.

**Передача всей истории по умолчанию.** Работает, пока диалог короткий; потом внезапно дорожает и начинает чудить.

**Передача управления вместо вызова функции.** Если «агент» ничего не решает сам, а просто выполняет шаг, это узел, а не агент. Handoff нужен там, где следующий исполнитель ведёт собственный диалог с моделью.
