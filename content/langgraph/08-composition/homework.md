# Домашнее задание: разложить наставника на части

## Задача 1. Проверка ДЗ становится подграфом

Вынесите веер проверки домашнего задания (модуль 03) вместе со спойлер-гейтом (модуль 06) в отдельный граф со своей схемой состояния: на входе — текст решения и признаки, на выходе — вердикт и список проверок.

Подключите его к графу наставника функцией-обёрткой. Убедитесь, что:

- подграф запускается отдельно, своим `invoke`, и его можно тестировать без родителя;
- прерывание спойлер-гейта изнутри подграфа доходит до вызывающего кода;
- при стриме с `subgraphs=True` видны события изнутри подграфа.

## Задача 2. Два агента и маршрутизация

Разделите наставника на двух агентов: `theory` (объясняет материал, инструменты поиска по урокам) и `homework` (проверяет решения). У каждого свой системный промпт и свой список инструментов.

Маршрутизацию сделайте **без** супервизора-агента: классификатор из модуля 02 уже умеет определять тип запроса. Сравните с вариантом на `create_supervisor` и запишите для себя, во что обошёлся лишний вызов модели: по времени ответа и по числу вызовов.

## Задача 3. Передача управления

Добавьте в агента `homework` handoff-инструмент: если из решения видно, что студент не понял тему, разговор передаётся агенту `theory` с указанием причины.

Требования: инструмент возвращает `Command` с `graph=Command.PARENT`, создаёт свой `ToolMessage`, кладёт причину в состояние и не передаёт теоретику всю историю проверки — только причину и исходный вопрос. Передач за один запрос не больше двух.

## Задача 4. Ночной обход курса на Functional API

Напишите `audit_course(course_id)` через `@entrypoint` и `@task`: для каждого урока курса — задача, которая ищет в тексте термины, использованные до определения, и противоречия с другими уроками; в конце — сводный отчёт.

Задачи должны выполняться параллельно, а прогон — переживать перезапуск: повторный вызов на той же нити не пересчитывает уже проверенные уроки.

## Как проверить себя

- Подграф проверки ДЗ запускается сам по себе, и его тест не требует родительского графа. Если для теста нужен весь наставник — контракт получился неявным.
- При отказе от `subgraphs=True` события изнутри подграфа исчезают из потока. Посмотрите на это специально: так выглядит «интерфейс замер» в самом долгом месте.
- Узел, передающий управление в родителя, **не** аннотирован `Command[Literal[...]]`. С аннотацией граф не компилируется: движок ищет несуществующий узел внутри подграфа.
- Handoff-инструмент добавляет `ToolMessage` со своим `tool_call_id`. Без него следующий вызов модели упадёт.
- Теоретик после передачи не видит истории проверки признаков. Проверьте по числу сообщений в его входе.
- Два агента не перекидывают разговор по кругу: счётчик передач ограничивает это принудительно.
- Прогон `audit_course` прерывается на середине (уберите процесс), запускается заново на той же нити и не пересчитывает уже проверенные уроки. Если пересчитывает — побочная работа оказалась в теле `entrypoint`, а не в задаче.
- Сравните две версии маршрутизации честно: классификатор против супервизора. Запишите числа — они пригодятся при обсуждении «а давайте сделаем мультиагентную систему».
