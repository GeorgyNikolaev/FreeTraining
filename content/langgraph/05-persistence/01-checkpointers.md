# Чекпойнты и нити: агент, переживающий перезапуск

До сих пор каждый вызов графа начинался с чистого листа. Студент спросил, наставник ответил, состояние умерло вместе с вызовом. Чтобы диалог продолжался, состояние надо сохранять — этим занимается чекпойнтер (checkpointer).

## Одна строка, меняющая всё

```python
from langgraph.checkpoint.memory import InMemorySaver

graph = builder.compile(checkpointer=InMemorySaver())

config = {"configurable": {"thread_id": "student-42:langgraph"}}
graph.invoke({"messages": [{"role": "user", "content": "что такое редьюсер?"}]}, config)
graph.invoke({"messages": [{"role": "user", "content": "а если их два?"}]}, config)
```

Второй вызов продолжает первый: модель увидит оба вопроса и свой предыдущий ответ. Ничего передавать вручную не нужно — состояние восстанавливается из сохранённого снимка по `thread_id`.

**Нить (thread)** — это последовательность снимков состояния с общим `thread_id`. Для наставника естественная нить — «этот студент в этом курсе»: диалог продолжается, когда он возвращается к учёбе, но вопросы по разным курсам не мешаются.

Про `thread_id` полезно знать две вещи: он задаётся вами (движок не придумывает его сам) и у него есть ограничение длины — 255 символов.

## Что именно сохраняется

Снимок (`StateSnapshot`) делается после каждого супершага и содержит:

| Поле | Что внутри |
|---|---|
| `values` | состояние целиком, все поля |
| `next` | узлы, которые должны выполниться следующими; пустой кортеж — граф завершён |
| `config` | `thread_id` и `checkpoint_id` этого снимка |
| `parent_config` | ссылка на предыдущий снимок |
| `metadata` | источник обновления и номер шага |
| `tasks` | задачи, запланированные и не выполненные |
| `interrupts` | активные прерывания (модуль 06) |

Ключевое здесь — `next` и `tasks`. Сохраняется не только «что получилось», но и «что предстоит»: поэтому прерванный на середине граф можно продолжить, а не запустить заново.

```python
snapshot = graph.get_state(config)
print(snapshot.values["messages"][-1].text)
print(snapshot.next)          # () — граф завершён
```

## Вход при продолжении нити

Частый источник недоразумений: что происходит со входным словарём при втором вызове на той же нити. Ответ — с ним работают обычные правила обновления состояния. Поле с редьюсером дополняется, поле без редьюсера — заменяется.

Проверено на langgraph 1.2.11: граф с полями `log: Annotated[list, add]` и `n: int` после первого запуска имел `{"log": ["a","b"], "n": 2}`. Второй вызов с входом `{"log": ["новый вход"], "n": 100}` дал `{"log": ["a","b","новый вход","a","b"], "n": 102}` — список дополнился, число заменилось, и граф прошёл свои узлы заново.

Для наставника это ровно то поведение, которое нужно: в `messages` с редьюсером `add_messages` попадает только новый вопрос, а вся история подтягивается сама.

## Нить и пользователь — разные вещи

Нить хранит **ход конкретного разговора**. Она не знает, что этот студент уже полгода учится и вечно спотыкается о редьюсеры: то, что должно пережить смену разговора, живёт в другом месте — в долговременной памяти (последний урок модуля).

| | Нить (чекпойнтер) | Долговременная память (Store) |
|---|---|---|
| Границы | один разговор | всё, что знаем о студенте |
| Ключ | `thread_id` | пространство имён, например `("students", "u-42", "facts")` |
| Что хранит | сообщения, промежуточные поля, что делать дальше | факты, предпочтения, выводы |
| Кто пишет | движок автоматически | ваш код осознанно |

## Что это даёт, кроме памяти

Чекпойнты — фундамент, на котором стоят три следующие возможности курса:

- **Продолжение после сбоя.** Процесс упал между узлами — состояние на диске, запуск продолжается с того же места.
- **Человек в цикле.** Граф останавливается, ждёт ответа человека хоть сутки и продолжает (модуль 06). Без сохранённого состояния ждать было бы нечем.
- **Разбор полётов.** История снимков показывает, что происходило на каждом шаге, и позволяет вернуться назад (третий урок модуля).

## Выбор чекпойнтера

| Реализация | Пакет | Когда |
|---|---|---|
| `InMemorySaver` | входит в `langgraph` | тесты и отладка; умирает вместе с процессом |
| `PostgresSaver` / `AsyncPostgresSaver` | `langgraph-checkpoint-postgres` | продакшен; у нас уже есть Postgres |
| `ShallowPostgresSaver` | тот же пакет | когда история снимков не нужна, хранится только последний |
| Redis, SQLite и другие | отдельные пакеты | по обстоятельствам |

Наставник поедет на Postgres — он уже поднят в `docker-compose.yml` этого репозитория. Об этом следующий урок.

## Типичные ошибки

**Чекпойнтер без `thread_id`.** Вызов графа со скомпилированным чекпойнтером, но без `thread_id` в конфигурации, — ошибка на запуске. Забыть легко: в разработке граф часто вызывают без конфигурации.

**Один `thread_id` на всех.** Захардкоженный `"default"` означает, что все студенты пишут в один разговор и читают чужие сообщения. Идентификатор нити должен содержать идентификатор пользователя.

**Нить как база данных.** В состоянии не место данным, которые нужны вне разговора: прогрессу, результатам тестов, профилю. Они живут в вашей базе, а граф достаёт их инструментами.

**Бесконечно растущая нить.** Каждый снимок — это состояние целиком. Диалог на двести сообщений превращает каждый шаг в мегабайт. Подрезка истории — в последнем уроке модуля.
