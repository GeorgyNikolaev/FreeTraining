# Фоновые прогоны и остановка без потерь

Ответ студенту живёт секунды. Но у наставника есть и вторая работа: ночной обход курса — пройти по урокам, найти термины, использованные до определения, противоречия между уроками, устаревшие утверждения. Это десятки вызовов модели и десятки минут.

Такой прогон не привязан ни к какому HTTP-запросу, и правила для него другие.

## Свойства долгого прогона

**Никто не ждёт ответа.** Запускающий код получает идентификатор нити и уходит; результат забирают позже из состояния.

**Он обязан переживать перезапуск.** Деплой посреди обхода не должен означать «начать сначала» — отсюда `durability="sync"` или хотя бы `"async"` и осмысленное разбиение на задачи (Functional API из модуля 08 подходит идеально).

**Его надо уметь остановить.** Не «убить процесс», а завершить текущий шаг и сохранить состояние.

## Остановка без потерь

В langgraph 1.2 появился кооперативный слив (drain): вы просите прогон остановиться, он доделывает текущий шаг, сохраняет снимок и завершается.

```python
from langgraph.runtime import RunControl

control = RunControl()


def on_sigterm(*_):
    control.request_drain("деплой")       # обработчик сигнала от системы


result = graph.invoke(payload, config, control=control)
```

Проверено на langgraph 1.2.11: после `request_drain` прогон завершается исключением `GraphDrained: Graph drained: деплой`, а в состоянии остаётся всё, что успело выполниться, и `next` указывает на следующий шаг. Продолжение — обычный запуск на той же нити с входом `None`:

```python
graph.invoke(None, config, control=RunControl())    # доигрывает с места остановки
```

Для веб-приложения это значит вот что: при получении `SIGTERM` вы не обрываете прогоны, а просите их слиться, и после выкатки новой версии они продолжаются сами. Контроль создаётся **на каждый прогон** — использовать один и тот же повторно нельзя, он остаётся в состоянии «слит».

## Расписание

Запуск по расписанию в самой библиотеке не предусмотрен — это работа окружения:

| Вариант | Как |
|---|---|
| Планировщик сервера LangGraph | создание задания через SDK (`crons.create`), если сервер используется |
| Системный планировщик | `cron` или таймер systemd, запускающий скрипт с графом |
| Планировщик приложения | фоновая задача в FastAPI или отдельный воркер |

Для платформы проще третий вариант: команда в `agent/scripts/audit.py`, запускаемая по расписанию хоста. Важно только, чтобы повторный запуск на той же нити продолжал работу, а не начинал заново.

## Результат долгого прогона

Отдавать отчёт «в ответ» некому, поэтому решите заранее, где он оседает:

- **В состоянии нити.** Просто и достаточно для разового отчёта: по `thread_id` можно достать результат в любой момент.
- **В таблице платформы.** Правильнее, если отчётом кто-то пользуется: у ночного обхода это список замечаний по урокам, который логично показывать в интерфейсе автора курса.
- **В долговременной памяти.** Для выводов, которыми будет пользоваться сам агент.

## Гигиена нитей

Фоновые прогоны копят нити быстрее диалогов. Заведите правило и процедуру сразу:

- прогоны обхода курса — хранить последние N, остальные удалять;
- диалоговые нити без активности дольше X месяцев — удалять;
- нити, зависшие на прерывании (модуль 06), — закрывать по таймеру.

У чекпойнтера есть методы удаления нити и очистки старых снимков, у клиента сервера — `threads.delete` и `threads.prune`. Без такой уборки таблица чекпойнтов становится крупнейшей в базе — и обнаруживается это в неподходящий момент.

## Отмена и наблюдение

Для фоновых прогонов нужны две операции, которые в диалоге не требуются: «покажи, что сейчас идёт» и «останови вот этот». Если вы работаете библиотекой, обе пишутся сами: список активных прогонов — своя таблица, отмена — тот же `RunControl`, сохранённый по идентификатору прогона. Если сервером — они есть готовыми (`runs.list`, `runs.cancel`, `runs.join_stream` для подключения к идущему потоку).

## Типичные ошибки

**Обрыв процесса вместо слива.** Прогон умирает посреди шага; при `durability="async"` теряется последний снимок, и непонятно, что успело выполниться.

**Повторное использование `RunControl`.** Объект после слива остаётся «слитым»: следующий прогон с ним завершится немедленно.

**Фоновый прогон без ограничения стоимости.** Обход курса из тридцати уроков — это тридцать с лишним вызовов модели. Прикиньте стоимость до первого запуска и поставьте лимит на число задач.

**Перезапуск вместо продолжения.** Скрипт, который каждую ночь начинает обход заново на новой нити, не пользуется ничем из этого модуля. Продолжение на той же нити — смысл всей конструкции.
