# Тесты для графа

Агент недетерминирован: та же формулировка даёт разные ответы. Отсюда частый вывод — «тестировать бессмысленно», и он неверен. Недетерминирована только модель; всё остальное в графе — обычный код, который отлично проверяется.

Делим проверки на три уровня: узлы и маршрутизаторы, граф на подменённой модели, качество ответов (следующий урок).

## Уровень 1: узлы и маршрутизаторы — обычные функции

```python
def test_отказ_объясняет_причину():
    state = {"question": "напиши письмо", "is_on_topic": False, "reason": "не про курс"}
    assert refuse(state)["answer"].startswith("Это вне курса")


def test_маршрут_по_теме():
    assert route({"is_on_topic": True}) == "answer"
    assert route({"is_on_topic": False}) == "refuse"
```

Ни графа, ни модели, ни базы: узел — это функция из состояния в словарь обновлений. Такие тесты стоит писать на всё, где есть условие: маршрутизаторы, редьюсеры, разбор признаков из `homework.md`, обрезку истории.

Редьюсер проверяется особенно легко и окупается сразу:

```python
def test_редьюсер_не_дублирует_и_умеет_сбрасывать():
    assert merge_sources(["a"], ["a", "b"]) == ["a", "b"]
    assert merge_sources(["a"], []) == []
```

## Уровень 2: граф на подменённой модели

Чтобы проверить сам граф — маршруты, циклы, работу с инструментами — модель подменяют заранее заданными ответами.

```python
from langchain.messages import AIMessage
from langchain_core.language_models.fake_chat_models import FakeMessagesListChatModel

fake = FakeMessagesListChatModel(responses=[
    AIMessage(content="", tool_calls=[{"name": "search_lessons",
                                       "args": {"query": "редьюсер"}, "id": "call_1"}]),
    AIMessage(content="Редьюсер объединяет значения."),
])
```

Такая модель отдаёт ответы по порядку: сначала вызов инструмента, потом финальный ответ. Этого достаточно, чтобы проверить весь ReAct-цикл — что инструмент был вызван, что результат вернулся модели, что цикл завершился.

Подменять модель удобнее всего через контекст запуска (модуль 04): в проде туда кладётся настоящая, в тесте — фейковая. Тогда подмена не требует ни патчей, ни глобальных переменных.

Что проверять на этом уровне:

| Проверка | Как |
|---|---|
| Ветка выбрана верно | по значению полей состояния в результате |
| Инструмент вызван с нужными аргументами | по `tool_calls` в истории сообщений |
| На каждый вызов есть ответ | пройти по `messages` и сопоставить `tool_call_id` |
| Цикл завершается | счётчик вызовов модели в состоянии; фейковая модель, всегда просящая инструмент |
| Ошибка инструмента не роняет запуск | инструмент, бросающий исключение, + `handle_tool_errors` |

Проверено на langgraph 1.2.11: все пять сценариев работают на фейковой модели без единого обращения к провайдеру.

## Тесты прерываний

Прерывание делает граф детерминированным в нужной точке — это подарок для тестов.

```python
def test_спойлер_гейт_не_выдаёт_решение_без_спроса():
    config = {"configurable": {"thread_id": "тест-1"}}
    first = graph.invoke(payload, config)
    assert first["__interrupt__"][0].value["вопрос"].startswith("Показать готовое решение")

    final = graph.invoke(Command(resume="мусор"), config)
    assert final["answer"] == "подсказка"        # неожиданный ответ = безопасное значение
```

Второй сценарий важнее первого: он проверяет, что произвольное значение из `resume` не ломает узел.

Отдельный тест — на повторное выполнение узла (модуль 06): счётчик побочного действия после `resume` должен остаться равным единице. Если он стал двойкой, необратимое действие стоит **до** `interrupt`.

В тестах всегда берите `InMemorySaver` и уникальный `thread_id` на тест: общий идентификатор превращает тесты в зависимые друг от друга.

## Где это живёт в репозитории

В платформе уже есть `pytest` с `asyncio_mode = "auto"` — асинхронные тесты пишутся без декораторов. Тесты агента кладите рядом с ним: `agent/tests/`, по файлу на тему — узлы, маршрутизация, инструменты, прерывания.

Полезная привычка: заведите набор фикстур с фейковыми моделями под типовые сценарии (сразу отвечает, зовёт инструмент один раз, зациклился) — и новые тесты будут писаться в три строки.

## Типичные ошибки

**Тест на текст ответа модели.** `assert "редьюсер" in answer` — проверка модели, а не графа: она сломается от смены версии модели или температуры. Проверяйте маршруты, вызовы и структуру, а качество текста — отдельно (следующий урок).

**Тесты, ходящие в настоящий API.** Медленно, дорого, нестабильно, а в CI ещё и требует ключа. Настоящая модель нужна ровно в одном месте — в оценке качества, и запускают её по расписанию, а не на каждый коммит.

**Общий `thread_id`.** Состояние от одного теста протекает в другой, и падать начинает то один, то другой.

**Проверка только счастливого пути.** Ошибка инструмента, отказ человека, пустой результат поиска, превышение лимита итераций — именно эти ветки ломаются при доработках, потому что их никто не смотрит глазами.
