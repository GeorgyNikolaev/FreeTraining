# Видеть, что происходит: трейсинг и стоимость

Агент ответил не так. Логов нет, а если есть — в них строка «ответ отправлен». Чтобы разбираться, нужен трейс: дерево вызовов с промптами, ответами модели, вызовами инструментов и таймингами.

## LangSmith в три переменные

LangSmith — сервис наблюдаемости от тех же авторов, и включается он без изменений в коде:

```bash
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=lsv2_...
LANGCHAIN_PROJECT=freetraining-tutor      # необязательно: имя проекта
```

Всё, что вызывается через LangChain и LangGraph, начинает отправлять трейсы автоматически: каждый узел, каждый вызов модели с полным промптом, каждый вызов инструмента с аргументами и результатом, длительности и расход токенов. Свой код, который ходит мимо LangChain, добавляют в трейс декоратором `@traceable`.

Для не-американских регионов есть переменная `LANGSMITH_ENDPOINT`. Тарифы сервиса меняются — проверяйте актуальные перед тем, как включать трейсинг на всю аудиторию.

## Что реально спасает время

| Вопрос | Где ответ в трейсе |
|---|---|
| Почему агент выбрал не тот инструмент | промпт вызова модели: видно описание инструментов и историю |
| Почему ответ «из головы» | вход узла `answer`: подложился ли текст урока |
| Почему медленно | длительности шагов: обычно один вызов модели или последовательный веер |
| Почему дорого | токены по шагам: обычно раздутая история сообщений |
| Что вернул инструмент | вход и выход вызова инструмента целиком |

Самое частое открытие при первом взгляде на трейс — в промпт уезжает гораздо больше, чем казалось: вся история, все результаты инструментов, весь текст урока.

## Чем это дополнить

Трейсинг не отменяет двух вещей из предыдущих модулей.

**Состояние как источник правды.** Решение, принятое узлом, должно лежать в состоянии (`reason`, `is_on_topic`, `handoff_reason`). Тогда причину видно и в снимке нити, а не только в трейсе — это важно, когда разбираться надо через месяц, а трейсы уже истекли по сроку хранения.

**История снимков.** `get_state_history` из модуля 05 показывает, как менялось состояние, и позволяет воспроизвести ситуацию, а не только посмотреть на неё.

## Если LangSmith нельзя

Иногда внешний сервис недопустим: персональные данные, контур без интернета. Тогда минимальный набор, который закрывает большую часть нужд, собирается из того, что уже есть:

```python
async for mode, chunk in graph.astream(payload, config, stream_mode=["tasks", "updates"]):
    if mode == "tasks":
        log.info("шаг", extra={"узел": chunk["name"], "ошибка": chunk.get("error")})
```

Режим `tasks` даёт старт и финиш каждого узла с входом, результатом и ошибкой — это уже структурированный лог выполнения. Плюс сохранённые снимки, плюс расход токенов из метаданных ответов модели (`response_metadata`), которые можно складывать в своё поле состояния.

## Деньги

Расход стоит считать с самого начала, потому что он растёт незаметно. Два правила, которые дают больше всего экономии:

- **Смотрите на длину истории, а не на число вызовов.** Вызовов может быть три, но если каждый тащит сорок сообщений, платите вы за контекст. Подрезка из модуля 05 — самый действенный рычаг.
- **Разные модели на разные роли.** Классификация вопроса и проверка одного признака ДЗ — это короткие задачи, для которых дешёвая модель обычно работает не хуже. Ответ студенту — та задача, где стоит платить.

Положите расход в состояние (сумма токенов по шагам) и отдавайте в метриках: «средняя стоимость ответа наставника» — число, которое стоит знать до того, как придёт счёт.

## Типичные ошибки

**Трейсинг включён в проде без разбора.** В трейс уезжают промпты целиком, а в них — вопросы студентов и куски их решений. Решите заранее, что допустимо отправлять во внешний сервис, и вырезайте лишнее (в LangChain для этого есть middleware, вырезающий персональные данные).

**Отладка по финальному ответу.** Ответ — последняя строка длинной цепочки; причина почти всегда раньше.

**Логи вместо состояния.** Если причина решения есть только в логе, воспроизвести ситуацию нельзя: нить восстанавливается из состояния, а лог к ней не привязан.

**Замер стоимости «потом».** К моменту, когда счёт станет заметным, у вас уже будет десять графов и ни одного числа для сравнения.
