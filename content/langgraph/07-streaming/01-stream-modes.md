# Режимы стрима: что именно отдавать наружу

Наставник отвечает пять-десять секунд: модель думает, инструменты ищут по урокам, проверка ДЗ идёт веером. Молчащий интерфейс все эти секунды выглядит как зависший. Значит, из графа надо отдавать не только итог, но и ход работы.

`invoke` возвращает итог. `stream` (и асинхронный `astream`) отдаёт происходящее по мере работы, а что именно — задаёт `stream_mode`.

## Шесть режимов

```python
for chunk in graph.stream(payload, config, stream_mode="updates"):
    print(chunk)
```

| Режим | Что приходит | Когда нужен |
|---|---|---|
| `values` | всё состояние после каждого шага | отладка, простая синхронизация состояния с интерфейсом |
| `updates` | только то, что вернул узел: `{"имя_узла": {...}}` | основной режим для «что происходит сейчас» |
| `messages` | токены от модели парами `(токен, метаданные)` | печать ответа по мере генерации |
| `custom` | то, что вы сами отправили из узла | свои события: «ищу в уроках», «проверяю признак 3 из 5» |
| `tasks` | старт и финиш каждой задачи, включая ошибки | диагностика, метрики по узлам |
| `checkpoints` | события сохранения снимков | редко; при разборе проблем с сохранением |

Есть ещё `debug` — объединение `checkpoints` и `tasks`.

Вот реальный вывод одного и того же графа из двух узлов (langgraph 1.2.11):

```
stream_mode="values"
  {'log': [], 'n': 0}
  {'log': ['a'], 'n': 1}
  {'log': ['a', 'b'], 'n': 2}

stream_mode="updates"
  {'a': {'log': ['a'], 'n': 1}}
  {'b': {'log': ['b'], 'n': 2}}

stream_mode="tasks"
  {'id': '7b7b…', 'name': 'a', 'input': {...}, 'triggers': ('branch:to:a',)}
  {'id': '7b7b…', 'name': 'a', 'error': None, 'result': {'log': ['a'], 'n': 1}, 'interrupts': []}
```

Разница между `values` и `updates` важна для веб-приложения: `values` отдаёт состояние целиком на каждом шаге, то есть историю сообщений, контекст урока и всё остальное — по сети, много раз. `updates` отдаёт только изменения.

## Несколько режимов сразу

```python
for mode, chunk in graph.stream(payload, config, stream_mode=["updates", "messages", "custom"]):
    ...
```

Когда режимов несколько, каждый элемент — пара «режим, данные», и можно разложить их по разным типам событий для клиента. Для наставника это рабочая комбинация: `messages` — токены ответа, `custom` — «что делаю сейчас», `updates` — законченные шаги.

## Токены модели

```python
async for token, meta in graph.astream(payload, config, stream_mode="messages"):
    if meta["langgraph_node"] == "answer":
        yield token.text
```

Метаданные говорят, какой узел породил токен, — без этого вы отдадите пользователю и токены служебных вызовов: классификации, рецензии, проверки признаков ДЗ. Фильтр по имени узла здесь обязателен.

Проверено на langgraph 1.2.11: режим отдаёт по одному фрагменту на кусок текста, в метаданных есть `langgraph_node`.

Важно: токены появятся, только если сама модель поддерживает потоковую выдачу и вызвана внутри узла обычным способом. Модель, обёрнутая в структурированный вывод, отдаёт результат целиком — стримить там нечего.

## Стрим из подграфов

По умолчанию события внутренних графов наружу не выходят. Чтобы их увидеть:

```python
for namespace, chunk in graph.stream(payload, config, stream_mode="updates", subgraphs=True):
    print(namespace, chunk)
```

`namespace` — путь до узла, внутри которого работает подграф. Подграфы — тема модуля 08, но флаг стоит запомнить сразу: без него «ничего не происходит» ровно в тот момент, когда работы больше всего.

## Что это меняет для наставника

Интерфейс урока получает три вида событий: «наставник ищет по урокам» (свои события), сам ответ по буквам (токены) и «шаг завершён» (обновления). Итог — по-прежнему в состоянии; стрим ничего не хранит и ничего не заменяет.

Отдельный практический момент: прерывание из модуля 06 приходит в поток как обычное событие, и клиенту надо уметь его показать. Разберём это в третьем уроке модуля, когда будем собирать эндпоинт.

## Типичные ошибки

**`values` в веб-интерфейсе.** Самая дорогая ошибка модуля: вы гоните всё состояние на каждом шаге. На длинном диалоге это мегабайты по сети за один ответ.

**Токены без фильтра по узлу.** Студент видит, как наставник «думает вслух» служебными вызовами: классификация, рецензия, проверка признаков. Выглядит как утечка внутренностей, потому что это она и есть.

**Стрим без чекпойнтера там, где нужна пауза.** Стриминг и сохранение состояния — разные вещи. Поток кончится, а нить не сохранится, если чекпойнтер не подключён.

**Попытка стримить структурированный вывод.** Поля появятся все сразу в конце: промежуточного состояния у разбора JSON нет.
