# Монолит или микросервисы: решение по фактам

Модульный монолит — одно развёртываемое приложение с чёткими внутренними модулями. Микросервисы — несколько независимо развёртываемых сервисов с собственными границами данных и сетевым взаимодействием. Это не шкала «зрелости».

| Критерий | Модульный монолит | Микросервисы |
| --- | --- | --- |
| Развёртывание | Одно | Независимое |
| Транзакции | Проще, внутри БД | Нужна eventual consistency |
| Наблюдаемость | Проще | Нужны трассировка и корреляция |
| Командная цена | Ниже | Выше: CI/CD, сеть, контракты |

Для сервиса записи разумно начать с модульного монолита: модули расписания, записи и уведомлений живут в одном приложении, но не обращаются к таблицам друг друга напрямую. Выделение сервиса оправдано, когда есть стабильная бизнес-граница, отдельная команда и реальная нужда выпускать или масштабировать его отдельно.

**Не повод для микросервисов:** «так модно», маленькая команда, отсутствие мониторинга, неясные границы домена. Сеть добавит задержки, частичные отказы и сложность согласования данных.
