# REST-контракт: ресурс, действие и результат

API-контракт — соглашение между клиентом и сервисом. Он описывает не таблицы БД, а устойчивую модель для потребителя. В REST ресурс называют существительным, а HTTP-метод передаёт действие.

| Операция | Метод и путь | Успех |
| --- | --- | --- |
| Получить слоты | `GET /slots?doctorId=42&date=2026-09-20` | `200` |
| Создать запись | `POST /appointments` | `201` + созданный ресурс |
| Прочитать запись | `GET /appointments/{id}` | `200` |
| Отменить запись | `POST /appointments/{id}/cancellation` | `200` |

`POST /appointments` получает `slotId` и данные клиента. Не доверяйте цене или статусу из браузера: сервер определяет их по правилам. Для повторяемой команды клиента используйте `Idempotency-Key`: повтор после сетевого сбоя вернёт прежний результат и не создаст вторую запись.

Фильтр, сортировка и пагинация должны быть согласованы. Для списка слотов укажите максимальный `limit`, формат cursor и порядок. Возвращать «все записи» без границ — скрытая проблема производительности.
