# Реляционные данные и SQL для аналитика

SQL нужен аналитику не для разработки приложения, а чтобы проверить гипотезу, качество данных и эффект изменения. Запрос начинайте с малого набора полей и всегда думайте о кардинальности `JOIN`: один слот с несколькими тегами легко умножит строки.

```sql
SELECT a.id, s.starts_at, d.name
FROM appointment a
JOIN slot s ON s.id = a.slot_id
JOIN doctor d ON d.id = s.doctor_id
WHERE a.status = 'confirmed'
  AND s.starts_at >= CURRENT_DATE;
```

Поиск двойных активных записей:

```sql
SELECT slot_id, COUNT(*)
FROM appointment
WHERE status IN ('pending', 'confirmed')
GROUP BY slot_id
HAVING COUNT(*) > 1;
```

Нормализация устраняет дублирование и аномалии обновления. Не храните имя врача в каждой записи, если это справочная сущность. Но не превращайте нормализацию в догму: снимок цены услуги на момент оплаты может быть намеренно сохранён в записи для аудита.
