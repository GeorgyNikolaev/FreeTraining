# Синхронные и асинхронные интеграции

Синхронный вызов ждёт ответ сейчас: `Booking API → Payment API`. Он нужен, когда без ответа нельзя продолжить сценарий. Асинхронный обмен передаёт событие или команду в очередь: отправитель не ждёт завершения потребителя.

| Подход | Хорош для | Риск |
| --- | --- | --- |
| Sync HTTP | Проверить доступность, получить расчёт | Таймаут и каскадный отказ |
| Очередь/событие | Уведомления, аналитика, долгие операции | Дубликаты и задержка |
| Webhook | Сообщить внешней системе результат | Нужны подпись и повторная доставка |

Создание записи должно синхронно проверить доступность и зафиксировать запись. Отправку SMS лучше сделать асинхронно: временная недоступность провайдера не отменяет полезную запись. Не называйте любое сообщение «событием»: событие сообщает свершившийся факт (`AppointmentConfirmed`), команда просит действие (`SendNotification`).

У интеграции есть владелец, схема, версия, SLA, таймаут, политика повторов и способ наблюдения. Без этого «мы отправляем JSON» — не контракт.
