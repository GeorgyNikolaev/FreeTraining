# Приоритизация, изменения и трассировка

Приоритет — решение о последовательности, а не ярлык «важно». MoSCoW помогает начать разговор: Must — без этого нет минимально полезного релиза; Should — значимо, но можно отложить; Could — полезно при ресурсе; Won't — сознательно не делаем сейчас.

| Артефакт | Идентификатор | Связь |
| --- | --- | --- |
| Потребность | GOAL-01 | Сократить звонки администраторам |
| Требование | FR-12 | Клиент создаёт запись |
| Правило | BR-04 | Один активный клиент на слот |
| Тест | AT-12 | Повторная запись отклоняется |

Эта цепочка — трассировка. По ней видно, зачем существует API-поле и какие тесты надо обновить при смене правила. Не делайте огромную таблицу ради формальности: трассируйте рискованные и регулируемые части.

При изменении «разрешить перенос записи» сначала оцените последствия: статусы, доступность, уведомления, аудит, интеграции и тесты. Затем обновите решение и укажите версию. Изменение не является ошибкой; ошибкой является неуправляемое изменение.
