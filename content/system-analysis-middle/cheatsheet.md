# Шпаргалка системного аналитика

## Требования

| Вид | Проверка |
| --- | --- |
| Функциональное | Что система делает |
| Бизнес-правило | Какое ограничение домена действует |
| NFR | Какая метрика и при каких условиях достигнута |
| Критерий приёмки | Дано — Когда — Тогда, наблюдаемый результат |

Перед разработкой: цель и scope ясны, у правил есть владелец, крайние случаи описаны, контракт и данные согласованы, открытые вопросы имеют ответственного.

## BPMN

| Элемент | Используйте для |
| --- | --- |
| Событие | Факта: запрос получен, таймаут, ошибка |
| Задача | Работы: проверить слот, отправить уведомление |
| XOR | Одного пути по условию |
| AND | Параллельных действий |
| Pool/Lane | Участника/ответственности |
| Message flow | Сообщения между разными pool |

## Данные и архитектура

| Вопрос | Короткий ответ |
| --- | --- |
| SQL или NoSQL? | SQL — связи, транзакции и запросы; NoSQL — особая форма/масштаб данных, не замена модели |
| Монолит или микросервисы? | Начинайте с модульного монолита; выделяйте сервис при стабильной границе и независимой потребности |
| C4 Container | Приложение/хранилище, а не обязательно Docker |
| C4 Component | Значимая обязанность внутри одного Container |
| Кэш | Ускоряет чтение, но не источник истины для критичного решения |

Cache-aside: read cache → miss → read DB → set TTL → return. При записи инвалидируйте связанные ключи. Финальную доступность слота проверяйте в транзакции БД.

## API и интеграции

| Ситуация | Решение |
| --- | --- |
| Создан ресурс | `201` |
| Некорректный запрос | `400`/`422` по единой конвенции |
| Нет прав | `403` |
| Ресурс отсутствует | `404` |
| Конфликт состояния | `409` |
| Повтор POST после таймаута | `Idempotency-Key` |
| Нефатальное действие после записи | Асинхронное событие/очередь |

Событие сообщает факт, команда просит выполнить действие. Для событий: `eventId`, идемпотентный потребитель, ограниченный retry, DLQ. Outbox фиксируется с бизнес-изменением в одной транзакции.

## Качество и релиз

Пишите NFR в форме «метрика ≤/≥ значение при условиях». Передавайте trace ID, не логируйте секреты. У релиза есть мониторинг, фичефлаг при необходимости, план отката/forward-fix и владелец поддержки.
