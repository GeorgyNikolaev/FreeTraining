# Глоссарий

**Актор** — роль человека или внешней системы, взаимодействующая с системой
извне. Записывается ролью, а не должностью или фамилией.

**Атрибутное разграничение доступа (ABAC)** — модель, в которой право зависит от
свойств субъекта и объекта: отделения, назначения, авторства, времени.
Дополняет роли, определяя область видимости.

**Бизнес-правило** — утверждение о предметной области, истинное независимо от
реализации: ограничение, вычисление, признак или реакция на событие. Хранится в
каталоге с владельцем, датой вступления и версией.

**Бизнес-требование** — цель, ради которой создаётся система, выраженная числом
и сроком.

**Выгрузка** — передача данных за пределы системы файлом. Проектируется как
интеграция: ограниченный состав полей, журналирование, отдельные права.

**Граница системы** — множество решений и данных, за которые отвечает команда.
Всё остальное — смежные системы и акторы.

**Деградация** — заранее описанное поведение системы при отказе зависимости:
какая функция отключается, что видит пользователь.

**Идемпотентность** — свойство операции давать тот же результат при повторном
выполнении. Для создающих операций обеспечивается ключом идемпотентности,
который клиент присылает вместе с запросом.

**Ключ партиционирования** — значение, по которому брокер распределяет
сообщения; порядок гарантируется только внутри одного ключа.

**Компенсирующая операция** — действие, отменяющее эффект предыдущего шага, когда
транзакционный откат невозможен: снятие резерва, отзыв пакета документов.

**Контекстная диаграмма** — схема, где система показана одним блоком, а вокруг —
акторы и смежные системы с указанием инициатора и предмета обмена.

**Критерий приёмки** — проверяемое утверждение о наблюдаемом поведении системы,
из которого механически получается тест-кейс.

**Маскирование** — показ части значения вместо полного. Выполняется на сервере;
маска постоянна во всех интерфейсах.

**Мастер-данные** — данные, имеющие единственный источник истины; системы, не
владеющие ими, читают, но не изменяют их у себя.

**Минимизация данных** — принцип, по которому состав полей определяется задачей
пользователя: поле, не влияющее на его решение, не показывается.

**Нефункциональное требование (НФТ)** — требование к свойству системы —
скорости, доступности, сохранности, безопасности — выраженное метрикой,
значением, условиями измерения и последствием нарушения.

**Обезличивание** — необратимое преобразование, после которого данные нельзя
связать с конкретным лицом. Удаление одной фамилии обезличиванием не является.

**Область видимости** — множество объектов, к которым применимы права роли:
своё отделение, назначенные объекты, созданные самим субъектом.

**Оптимистическая блокировка** — механизм, при котором изменение принимается
только если версия объекта совпадает с известной клиенту; иначе возвращается
конфликт.

**Пессимистическая блокировка** — захват объекта за пользователем на время
работы; требует срока жизни, продления и принудительного снятия.

**Пилот** — запуск на ограниченной группе пользователей с заранее заданными
числовыми критериями расширения.

**Предохранитель (circuit breaker)** — механизм, временно прекращающий вызовы
сервиса после серии ошибок, чтобы не копить ожидающие запросы.

**Ролевое разграничение доступа (RBAC)** — модель, в которой набор операций
привязан к роли сотрудника.

**Сверка** — регулярное сопоставление данных двух систем по ключу для
обнаружения расхождений, невозможных по замыслу.

**Сегрегация обязанностей** — запрет на совмещение одним сотрудником
полномочий, дающих возможность выполнить операцию без контроля: например,
подготовку заявки и решение по ней.

**Снимок (снапшот)** — копия входных данных на момент принятия решения,
позволяющая объяснить решение спустя годы.

**Событие-уведомление** — сообщение, содержащее идентификаторы и тип изменения,
но не сами данные; получатель запрашивает детали по API с проверкой прав.

**Таблица исходящих (outbox)** — таблица, в которую сообщение записывается в той
же транзакции, что и изменение данных, и из которой отдельный процесс публикует
его в брокер.

**Таблица решений** — форма записи правила, где каждая строка — комбинация
значений условий с результатом; позволяет проверить полноту и найти противоречия.

**Трассируемость** — прослеживаемые связи «источник требования → требование →
реализация → тест», обязательные для требований, вытекающих из ограничений.

**Точка невозврата** — шаг процесса, после которого компенсация невозможна и
изменения выполняются только новыми операциями с участием человека.

**Уровень требований** — принадлежность формулировки к бизнес-, пользовательскому
или системному слою; смешение уровней в одном предложении делает требование
необсуждаемым.

**Экстренный доступ** — временное расширение прав с обязательным указанием
причины, ограничением срока, журналированием и уведомлением службы безопасности.

**Журнал доступа** — неизменяемая запись обращений к данным: кто, когда, к какому
объекту, какие разделы раскрыты, на каком основании, с каким результатом. Не
содержит значений самих данных.

**Журнал событий объекта** — история изменений состояния объекта, доступная
пользователям и поддержке.
