# Признаки поведения участника и пары

Ценовые показатели описывают закупку. Поведенческие описывают игрока и отношения между игроками — и именно они, как показано в модуле 01, несут основную часть сигнала.

## Признаки уровня участника

Все они считаются на историю **до** даты окончания подачи заявок по текущей закупке.

| Признак | Содержание | Почему работает |
|---|---|---|
| Число прошлых участий | Опыт игрока | Контекст для всех долей; отличает новичка от постоянного игрока |
| Доля побед | Победы / участия | Аномально высокая или ровная доля в сегменте |
| Доля пассивных участий | Заявка подана, ценовых предложений нет | Издержки участия без попытки победить |
| Средняя глубина снижения при победе | По выигранным закупкам | Систематически символическое снижение |
| Доля отклонённых заявок | Отклонения / участия | Регулярные дефекты в заявках |
| Концентрация по заказчикам | Индекс Херфиндаля по долям заказчиков | Работа с узким кругом заказчиков |
| Возраст участника | Дней с первого участия | Компании, созданные под конкретные торги |

Признак «доля пассивных участий» стоит выделить: он опирается на довод из модуля 02 о том, что участие стоит денег и требует внесения обеспечения. Систематическое участие без единого ценового предложения — поведение, которое трудно объяснить экономически.

## Расчёт без заглядывания в будущее

Для простых накопительных признаков достаточно сортировки по времени и кумулятивных сумм с вычитанием текущей строки:

```python
bids = bids.sort_values("dt_bids_end").reset_index(drop=True)
g = bids.groupby("participant_inn", sort=False)

bids["prev_n"] = g.cumcount()
bids["prev_wins"] = g["is_winner"].cumsum() - bids["is_winner"].astype(int)
bids["prev_passive"] = g["is_passive"].cumsum() - bids["is_passive"].astype(int)

denom = bids["prev_n"].where(bids["prev_n"] > 0)
bids["prev_win_rate"] = bids["prev_wins"] / denom
bids["prev_passive_rate"] = bids["prev_passive"] / denom
```

`cumcount()` даёт число предыдущих строк участника, а вычитание текущего значения из накопленной суммы убирает вклад самой закупки. Обе операции обязательны: без них признак содержит собственный исход закупки.

Для сложных признаков — индекса концентрации, состава контрагентов, сетевых метрик из следующего модуля — кумулятивный трюк не работает. Практичный приём: считать **снимки признаков на конец каждого квартала** и присоединять к закупке последний снимок, сделанный до её объявления.

```python
snapshots = []
for snap in pd.period_range("2021Q1", "2023Q4", freq="Q").to_timestamp(how="end"):
    hist = bids[bids["dt_bids_end"] <= snap]
    f = (
        hist.groupby("participant_inn")
            .apply(lambda s: pd.Series({
                "customer_hhi": (s["customer_inn"].value_counts(normalize=True) ** 2).sum(),
                "n_customers": s["customer_inn"].nunique(),
            }))
            .reset_index()
    )
    f["snapshot"] = snap
    snapshots.append(f)

feat = pd.concat(snapshots, ignore_index=True).sort_values("snapshot")

bids = pd.merge_asof(
    bids.sort_values("dt_bids_end"),
    feat,
    left_on="dt_bids_end",
    right_on="snapshot",
    by="participant_inn",
    direction="backward",
    allow_exact_matches=False,
)
```

`direction="backward"` берёт последний снимок до даты закупки, `allow_exact_matches=False` исключает совпадение дат. Этот приём пригодится и в модуле 06: граф участников строится ровно так же — снимками.

## Признаки уровня пары

| Признак | Содержание |
|---|---|
| Число совместных участий | Сколько раз пара встречалась на одних торгах |
| Доля совместных участий | Совместные / участия менее активного из двоих |
| Асимметрия побед в паре | Насколько односторонне распределены победы при встречах |
| Число встреч без торга | Совместные участия, где ни один не сделал предложения |
| Совпадение периодов активности | Появились и перестали участвовать одновременно |

Асимметрия побед — тонкий признак. Если при каждой встрече выигрывает один и тот же участник, это согласуется и со сговором, и с тем, что второй просто слабее. Признак работает в связке с другими: односторонние победы **плюс** отсутствие торга **плюс** высокая частота встреч — совсем другая картина, чем каждый из компонентов по отдельности.

Считать пары «в лоб» нельзя: число пар растёт квадратично. Практическое решение — строить пары только внутри закупок, а затем агрегировать:

```python
from itertools import combinations
import pandas as pd

def pairs_in_lot(participants):
    return list(combinations(sorted(participants), 2))

pair_rows = (
    bids.groupby("purchase_id")["participant_inn"]
        .apply(lambda s: pairs_in_lot(s.unique()))
        .explode()
        .dropna()
)
pair_counts = pair_rows.value_counts()
pair_counts = pair_counts[pair_counts >= 2]
```

Пары, встретившиеся один раз, отбрасываются сразу: они составляют подавляющее большинство и не несут информации.

## Тайминг

Если в ваших протоколах раскрыты отметки времени отдельных ценовых предложений — проверьте это на своей выгрузке, как рекомендовано в модуле 02, — становятся доступны сильные признаки: интервал между предложениями участников, порядок вступления в торг, доля торга, приходящаяся на последние минуты.

Если раскрыто только общее время торга, остаются производные признаки: длительность торга, число предложений, соотношение числа предложений и числа участников. Это меньше, но достаточно: длительность ровно в четыре минуты при пяти участниках — уже сигнал.

## Где ошибаются

**Считают долю побед у участника с одним участием.** Получается 0 или 1 — крайние значения, которые модель воспринимает как сильный сигнал. Доли нужно либо отмечать как отсутствующие при малом числе наблюдений, либо сглаживать, добавляя к числителю и знаменателю константу.

**Выбирают слишком длинное окно истории.** Поведение участника меняется: компания, активная пять лет назад, сегодня может быть другой. Разумная практика — считать признаки в двух окнах, полном и скользящем годовом, и дать модели оба.

**Забывают про холодный старт.** У участника, впервые вышедшего на торги, все накопительные признаки отсутствуют. Это не дефект данных, а содержательное состояние: заведите явный признак «первое участие». Компании, созданные незадолго до конкретной закупки и участвующие только в ней, — известный элемент нескольких схем.
