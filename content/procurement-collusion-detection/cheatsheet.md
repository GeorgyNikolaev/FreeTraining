## Схемы и их подписи в данных

| Схема | Подпись |
|---|---|
| «Таран» | Победитель со снижением около нуля + отклонены участники с самыми низкими ценами + большой разрыв до минимума + повторяющаяся тройка |
| Отказ от торга | Снижение около нуля при 3+ участниках, число предложений меньше числа участников, торг 4 минуты |
| Ротация побед | Ровное распределение побед в сегменте, победы слабо связаны с уровнем цен |
| Раздел рынка | **Аномально редкое** совместное участие пары при общем сегменте и регионе |
| Компенсация субподрядом | В открытых данных практически не виден |

Правило отбора кандидатов в «таран»:
`cheapest_rejected` **и** `drop_rate < 0.02` **и** `gap_to_min > 0.20` **и** `n_participants >= 3`

## Формулы скринингов

Предложения упорядочены: `b₍₁₎ ≤ b₍₂₎ ≤ … ≤ b₍ₙ₎`, `R` — НМЦК.

| Показатель | Формула | Аукцион |
|---|---|---|
| Глубина снижения | `(R − b_побед) / R` | Да |
| Разрыв до минимума | `(b_побед − b₍₁₎) / R` | Да |
| Число ценовых предложений | Счётчик | Да |
| Коэффициент вариации | `σ(b) / μ(b)`, при сговоре обычно **ниже** | Ограниченно |
| Размах | `(b₍ₙ₎ − b₍₁₎) / b₍₁₎` | Ограниченно |
| Относительная разница | `(b₍₂₎ − b₍₁₎) / b₍₁₎` | Ограниченно |
| Относительная дистанция | `(b₍₂₎ − b₍₁₎) / σ(b₍₂₎…b₍ₙ₎)`, при сговоре **выше**; нужно n ≥ 3 | Ограниченно |
| Эксцесс, асимметрия | Моменты распределения `b` | Нет |

Нормировка обязательна, внутри сегмента «ОКПД2 × регион», сегменты меньше 30 лотов отбрасываются:

## Нулевая модель графа

`N` — число лотов с двумя и более участниками, `a` и `b` — числа участий, `k` — число совместных.

- Ожидаемое число встреч: `a · b / N`
- Превышение: `lift = k / ожидаемое`
- Значимость: `p = hypergeom.sf(k − 1, N, a, b)`
- Поправка на множественность: Бенджамини — Хохберга (не Бонферрони)
- Пары с одной встречей отбрасываются до расчёта
- Раздел рынка — левый хвост того же распределения, кандидаты отбираются содержательно

Проверка, что граф измеряет связи, а не активность: корреляция степени с числом участий должна заметно упасть после перехода от сырых весов к превышению.

## Признаки

**Уровня участника (на историю до даты закупки):** число участий, доля побед, доля пассивных участий, средняя глубина снижения при победе, доля отклонённых заявок, индекс Херфиндаля по заказчикам, возраст участника, признак первого участия.

**Уровня пары:** число и доля совместных участий, асимметрия побед, число встреч без торга, совпадение периодов активности.

**Уровня графа (из снимка):** максимальное превышение связи среди пар лота, доля значимо связанных пар, доля участников из одного сообщества, средняя кластеризация, максимальный номер k-ядра, размер сообщества.

**Контекст:** число активных поставщиков в сегменте, число участников лота, НМЦК, признак единственного возможного исполнителя.

## Правила против утечки

1. Все признаки участника, пары и графа — строго по данным **до даты окончания подачи заявок**.
2. Кумулятивные признаки: `cumcount()` и `cumsum() − текущая строка`.
3. Сложные признаки и граф — **снимками на конец квартала**, присоединение через `merge_asof(direction="backward", allow_exact_matches=False)`.
4. Номер сообщества как признак использовать нельзя — нумерация не согласована между снимками.
5. Разделение по времени применяется и к построению графа, а не только к обучению модели.
6. Нормировка и отбор признаков считаются на обучающем окне и применяются к проверочному.
7. Первый год выборки уходит на разогрев графа и в обучении не участвует.
8. Проверка: разложение оценки по вкладам признаков — если наверху признак, которого не могло существовать, это утечка.

## Метрики

```python
def precision_at_k(y_true, score, k):
    order = np.argsort(-np.asarray(score), kind="stable")[:k]
    return float(np.asarray(y_true)[order].mean())

def lift_at_k(y_true, score, k):
    return precision_at_k(y_true, score, k) / float(np.mean(y_true))
```

- Основная метрика — точность в топ-k, `k` задаётся пропускной способностью проверки (порядка 50–100 на квартал).
- Дополняют: полнота в топ-k, выигрыш в топ-k, площадь под PR-кривой.
- Доля верных ответов и площадь под ROC-кривой при базовой частоте в доли процента непригодны.
- Приводить значения по каждому периоду и разброс, а не одно усреднённое число.
- Точность по меткам ФАС — нижняя оценка; дополняется ручным разбором головы списка.

## Порядок сборки датасета

1. Выгрузить извещения **и оба протокола**, сохранить сырьё, вести журнал выгрузки.
2. Единица наблюдения — лот; ИНН и номера читать строками.
3. Взять последнюю версию протокола, сохранив признак пересмотра.
4. Победителя брать из протокола подведения итогов, а не как минимум цены.
5. Закупки с одним участником вынести в отдельную ветку, не выбрасывать.
6. Прогнать проверки качества.

**Проверки качества:** число строк ставок совпадает с протоколом; `winner_price ≤ nmck`; ровно один победитель на лот; `dt_bids_end ≤ dt_auction ≤ dt_result`; ранги без пропусков; доля лотов без протокола итогов; график числа документов по дням без провалов.

## Готовые формулировки для раздела ограничений

1. Отрицательный класс означает отсутствие выявленного нарушения, а не отсутствие нарушения.
2. Выборка известных нарушений смещена приоритетами правоприменителя и содержит дела, раскрытые по заявлению участника, а не по следу в данных.
3. В свежем периоде метки отсутствуют из-за лага правоприменения.
4. Часть доказательственно значимых данных в открытых источниках отсутствует.
5. Результат модели — основание для проверки, а не вывод о нарушении; согласованность внутри группы лиц нарушением не является.

## Частые ошибки

| Ошибка | Последствие |
|---|---|
| Победитель = минимум цены | Стирается след «тарана» |
| ИНН прочитан как число | Участник распадается на двух, граф беднеет |
| Единица наблюдения — извещение | Многолотовые закупки ломают все показатели |
| Признаки по всей истории | Утечка, метрики завышены, на новых данных не работает |
| Граф с сырыми весами | Измеряется активность, а не связи |
| Сообщества ранжируются по плотности | В голове списка целые отрасли |
| Не учтена аффилированность | В топе законные группы лиц |
| Нормировка по всей выборке | Помечаются целые низкомаржинальные отрасли |
| Перекрёстная проверка с перемешиванием | Модель узнаёт компании, а не поведение |
| Отчёт по ROC-AUC | Метрика не различает модели на редком классе |
| Нет базового уровня в виде правила | Не с чем сравнить модель |
