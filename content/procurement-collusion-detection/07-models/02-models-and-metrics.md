# Модели и метрики

Выбор модели в этой задаче — не самая важная из ваших решений, и это стоит понимать заранее. Постановка и признаки определяют результат сильнее, чем алгоритм. Но выбрать всё равно нужно, и обосновать выбор придётся на защите.

## Начните с базового уровня

Первое, что должно появиться в работе, — не модель, а **правило**. Например, правило «тарана» из модуля 04 и правило «несколько участников, торга нет» из модуля 05.

Базовый уровень нужен по двум причинам. Он даёт число, с которым сравнивается всё последующее: модель, не превосходящая правило из трёх условий, не нужна. И он интерпретируем полностью, поэтому его результаты можно проверить вручную и убедиться, что данные и метки вообще связаны так, как вы думаете.

Работа, где сложная модель сравнивается только сама с собой, на защите выглядит неубедительно. Работа, где градиентный бустинг обошёл разумное правило в полтора раза по точности в голове списка, — убедительно.

## Классы моделей

| Класс | Представители | Сильные стороны | Ограничения |
|---|---|---|---|
| Правила | Пороговые условия по признакам схем | Полная прозрачность, не нужны метки | Не ловят комбинации, пороги подбираются вручную |
| Линейные | Логистическая регрессия с регуляризацией | Интерпретируемые коэффициенты, устойчивость при малой выборке | Не видит взаимодействий признаков |
| Ансамбли деревьев | Градиентный бустинг, случайный лес | Нелинейности и взаимодействия, работа с пропусками | Нужны метки; склонны запоминать конкретных участников |
| Обучение без учителя | Изолирующий лес, локальный уровень выброса | Метки не нужны, применимо ко всему массиву | Аномалия не равна нарушению |
| Обучение на положительных и неразмеченных данных | Двухшаговые методы, оценка доли положительных | Честно отражает природу разметки | Сложнее в реализации и объяснении |

Про обучение без учителя стоит сказать отдельно, потому что соблазн применить его «потому что меток нет» велик. Изолирующий лес находит наблюдения, непохожие на остальные, — но необычная закупка не обязательно сговорная, а сговорная закупка может быть совершенно обычной по всем измерениям, кроме тех, что относятся к схеме.

Вывод: применять методы поиска аномалий имеет смысл **не в сыром признаковом пространстве, а в пространстве признаков, специально сконструированных под схемы** из модуля 03. Тогда «аномалия» означает «необычно сильное проявление конкретной схемы», и это уже осмысленно.

## Метрики

Почему доля верных ответов и площадь под ROC-кривой здесь не работают, показано в модуле 01: при базовой частоте в доли процента обе метрики определяются поведением модели на подавляющем отрицательном классе.

Работающий набор:

| Метрика | Что измеряет | Когда использовать |
|---|---|---|
| Точность в топ-k | Доля настоящих нарушений среди k закупок с наибольшей оценкой | Основная метрика: прямо соответствует применению |
| Полнота в топ-k | Доля известных нарушений, попавших в топ-k | Дополняет точность: не пропускаем ли известное |
| Выигрыш в топ-k | Во сколько раз точность в топ-k выше базовой частоты | Сравнение моделей между сегментами с разной базовой частотой |
| Площадь под PR-кривой | Интегральное качество ранжирования на редком классе | Сводная метрика для сравнения моделей |

```python
import numpy as np

def precision_at_k(y_true, score, k):
    order = np.argsort(-np.asarray(score), kind="stable")[:k]
    return float(np.asarray(y_true)[order].mean())

def recall_at_k(y_true, score, k):
    y = np.asarray(y_true)
    order = np.argsort(-np.asarray(score), kind="stable")[:k]
    return float(y[order].sum() / y.sum()) if y.sum() else np.nan

def lift_at_k(y_true, score, k):
    base = float(np.mean(y_true))
    return precision_at_k(y_true, score, k) / base if base else np.nan
```

**Как выбрать k.** Не из соображений удобства, а из пропускной способности проверки. Территориальное управление способно углублённо разобрать порядка десятков закупок в квартал. Значит, осмысленные значения — `k = 50` или `k = 100` на квартал. Это число нужно назвать в работе и обосновать, иначе метрика повисает в воздухе.

**Как читать результат при неполной разметке.** Точность в топ-k, посчитанная по меткам из решений ФАС, — это **нижняя оценка**: часть закупок в вашем топе может быть настоящими нарушениями, по которым решения нет. Поэтому её обязательно дополняют ручным разбором головы списка, как в домашнем задании модуля 05. Формулировка в работе: «точность по известным меткам составила столько-то; при ручном разборе первых пятидесяти закупок ещё столько-то получили правдоподобное объяснение через схему».

## Интерпретируемость обязательна

Это не пожелание, а следствие постановки задачи. Результат модели поступает человеку, который должен решить, начинать ли проверку. Оценка без объяснения для этого бесполезна: проверяющему нужно знать, что именно выглядит подозрительно.

Практическое требование к вашей работе: **каждая закупка в верхней части списка сопровождается разложением оценки по вкладам признаков**. Для ансамблей деревьев это делается через значения Шепли (SHAP), для линейных моделей — напрямую через произведение коэффициента на значение признака.

Побочная польза: анализ вкладов — лучший способ поймать утечку. Если в топе вклада стоит признак, которого в момент объявления закупки существовать не могло, вы нашли ошибку, которую метрики не показали бы.

## Где ошибаются

**Сравнивают модели по площади под ROC-кривой.** На редком классе эта метрика почти не различает модели, сильно различающиеся по полезности в голове списка.

**Подбирают порог вероятности вместо работы со списком.** Задача не «классифицировать закупку», а «отранжировать и взять сколько успеем проверить». Порог здесь — производная величина от пропускной способности, а не параметр модели.

**Отчитываются средним по перекрёстной проверке без разброса.** При десятках положительных примеров точность в топ-k скачет между периодами очень сильно. Приводить нужно значения по каждому периоду и их разброс; единственное усреднённое число создаёт ложное впечатление устойчивости.
