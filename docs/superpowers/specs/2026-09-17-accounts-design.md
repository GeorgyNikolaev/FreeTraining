# Аккаунты — дизайн-документ

Дата: 2026-09-17
Статус: согласован

## 1. Что делаем

- Регистрация по имени, почте и паролю (пароль вводится один раз), без
  подтверждения почты.
- Вход по почте и паролю. Восстановления пароля пока нет.
- Сессии на JWT с хранением в Redis: короткий access-токен и сменяемый
  refresh-токен.
- Гостевой режим: курсы проходятся без аккаунта, прогресс сохраняется и
  переносится в аккаунт.
- Отзывы оставляют только вошедшие пользователи, в списке видно имя автора.
- Задел под подтверждение почты и восстановление пароля одноразовым кодом:
  сервисный слой без эндпоинтов и экранов.

## 2. Инфраструктура

- `docker-compose.yml`: сервис `redis` (`redis:8-alpine`) на порту **6380** —
  стандартный 6379 может быть занят локальным Redis.
- Зависимости бэкенда: `pyjwt`, `pwdlib[argon2]`, `redis`, `email-validator`.
- Настройки: `REDIS_URL`, `TEST_REDIS_URL` (отдельная база Redis),
  `JWT_SECRET` (обязательна: без неё приложение не стартует и подсказывает
  команду генерации), `ACCESS_TOKEN_TTL_SECONDS` = 900,
  `REFRESH_TOKEN_TTL_SECONDS` = 30 дней, `COOKIE_SECURE` = false.
- Настройка `USER_ID=local` удаляется.

## 3. База данных

Новая таблица `user_account`, создаётся `create_all`. Существующие таблицы не
меняются: `user_id` в них — id аккаунта (uuid строкой) или id гостя.

| Колонка | Тип | Назначение |
| --- | --- | --- |
| `id` | uuid, PK | |
| `email` | str, unique | в нижнем регистре, без пробелов по краям |
| `name` | str | 1–50 символов |
| `password_hash` | str | Argon2id |
| `email_verified_at` | timestamptz, null | задел под подтверждение почты |
| `password_changed_at` | timestamptz | задел под восстановление пароля |
| `created_at`, `updated_at` | timestamptz | |

Внешних ключей от таблиц прогресса нет: у гостя нет записи в `user_account`.

## 4. Токены и сессии

**Access-токен** — JWT HS256 на 15 минут. Поля: `sub` (id пользователя), `sid`
(id сессии), `type=access`, `iat`, `exp`. Фронтенд держит его только в памяти и
передаёт в `Authorization: Bearer`. При каждом запросе сервер проверяет подпись,
срок и существование сессии в Redis — выход и отзыв сессий действуют сразу.

**Refresh-токен** — 256 случайных бит, не JWT. Лежит в cookie `ft_refresh`
(`HttpOnly`, `SameSite=Strict`, `Path=/api/auth`). В Redis хранится только его
SHA-256.

Каждое обновление выдаёт новую пару и продлевает сессию на 30 дней: активный
пользователь не выходит из аккаунта. Повторное предъявление уже сменённого
токена позже чем через 20 секунд считается кражей — сессия отзывается. Окно в
20 секунд прощает одновременные запросы, а на фронтенде обновление идёт под
`navigator.locks`, чтобы вкладки не обновлялись одновременно.

Ключи Redis:

| Ключ | Значение |
| --- | --- |
| `auth:session:{sid}` | hash: `user_id`, `refresh_hash`, `created_at`, `user_agent`, `ip` |
| `auth:refresh:{hash}` | `sid` действующего токена |
| `auth:used:{hash}` | `sid` и время смены уже сменённого токена |
| `auth:user_sessions:{user_id}` | множество `sid` — для отзыва всех сессий |
| `auth:rl:login:{email}` | число неудачных входов |
| `auth:rl:register:{ip}` | число регистраций |

Все ключи сессии живут столько же, сколько refresh-токен.

**Защита от подбора.** 5 неудачных входов на почту за 15 минут, затем 429
«Слишком много попыток входа. Попробуйте через N мин.». Не больше 10
регистраций с одного IP в час.

**Перебор почт.** Любая ошибка входа — «Неверная почта или пароль». Если почты
нет, всё равно считается хеш, чтобы время ответа не выдавало ответ. Регистрация
на занятую почту честно отвечает 409 «Эта почта уже зарегистрирована».

## 5. API

Роутер `app/api/auth.py`.

| Метод и путь | Назначение |
| --- | --- |
| `POST /api/auth/register` | `{name, email, password}` → 201 `AuthSession`, cookie; гостевой прогресс переносится без вопроса |
| `POST /api/auth/login` | `{email, password}` → `AuthSession`, cookie; гостевой прогресс не трогается |
| `POST /api/auth/refresh` | refresh-токен из cookie → `AuthSession` с новой парой |
| `POST /api/auth/logout` | удаляет сессию и cookie, всегда 200 |
| `GET /api/auth/me` | `{user, guest_progress}` |
| `POST /api/auth/guest/merge` | перенести прогресс гостя в аккаунт |
| `POST /api/auth/guest/discard` | удалить прогресс гостя |

`AuthSession`:

```json
{
  "access_token": "…", "token_type": "bearer", "expires_in": 900,
  "user": { "id": "…", "name": "Георгий", "email": "…", "email_verified": false },
  "guest_progress": { "courses": 2, "lessons": 7, "attempts": 3 }
}
```

`guest_progress` — `null`, если у гостя на этом устройстве прогресса нет.

Проверки: пароль 8–128 символов без требований к составу, почта по
`email-validator`, имя 1–50 символов после обрезки пробелов. Нарушение — 422.

Зависимости в `deps.py` вместо `get_user_id`:

- `get_identity` — `Identity(user_id, is_guest)`. Недействительный или
  просроченный Bearer — 401, чтобы клиент обновил токен. Без заголовка — гость
  из cookie или новый гость, ещё не записанный в cookie.
- `get_writer_identity` — то же, но новому гостю выставляет cookie. Им пользуются
  эндпоинты записи прогресса.
- `require_user` — 401 «Войдите в аккаунт», если пользователь гость.

## 6. Гости и перенос прогресса

Гость появляется при первой записи прогресса: id `guest:<случайная строка>` в
cookie `ft_guest` (`HttpOnly`, `SameSite=Lax`, `Path=/api`, 1 год). Чтение без
cookie возвращает пустой прогресс и гостя не создаёт.

Перенос выполняется одной транзакцией:

- `lesson_progress` — объединение, при совпадении урока остаётся более раннее
  `completed_at`;
- `quiz_attempt` — все попытки переходят в аккаунт;
- `last_position` — по каждому курсу остаётся более свежая позиция;
- `course_review` — переходит, если у аккаунта нет отзыва на этот курс.

После переноса данные гостя удаляются, cookie `ft_guest` стирается.

**При регистрации** перенос делается сразу. **При входе** прогресс гостя не
трогается, а в ответе приходит `guest_progress`. Фронтенд показывает диалог:
«Перенести» или «Не переносить» — во втором случае прогресс гостя удаляется.
Пока выбор не сделан, диалог появляется снова при загрузке страницы. Пока
пользователь в аккаунте, прогресс пишется в аккаунт.

После выхода устройство снова работает как новый гость.

Прогресс прежнего пользователя `local` переносится командой:

```bash
uv run python -m app.cli claim-local --email you@example.com
```

## 7. Отзывы

- `PUT` и `DELETE /reviews/me` требуют вход, гостю — 401.
- `CourseReviews` получает `is_authenticated`, у гостя `can_review = false`.
- `ReviewOut` получает `author_name` (`null`, если аккаунта нет). Почта наружу
  не отдаётся.
- Вкладка «Отзывы» у гостя: `Callout` «Войдите, чтобы оставить отзыв» с кнопками
  «Войти» и «Зарегистрироваться», после входа возврат на вкладку.
- Предложение оценить пройденный курс у гостя ведёт на вход.

## 8. Фронтенд

- `lib/auth/session.ts` — access-токен в памяти, обновление одним запросом на
  все вкладки и вызовы.
- `apiFetch` добавляет `Authorization`. На 401 (кроме `/api/auth/*`) один раз
  обновляет токен и повторяет запрос. Не удалось — пользователь становится
  гостем.
- `AuthProvider` при старте тихо вызывает `/api/auth/refresh`. Пока ответа нет,
  страницы не рендерятся, чтобы не мигал прогресс гостя. После входа, выхода и
  переноса кеш запросов сбрасывается.
- Страницы `/login` и `/register`: карточка с формой, одна акцентная кнопка,
  ссылка на соседнюю страницу, параметр `?next=`. Ошибки — `Callout` `danger`.
  Уже вошедшего пользователя страницы отправляют на `next`.
- Шапка: гостю — кнопка «Войти», вошедшему — меню с именем, почтой и «Выйти».
- `GuestProgressDialog` — выбор переноса прогресса после входа.

### Дизайн-система

- `TextField` — однострочное поле с подписью, подсказкой и ошибкой.
- `PasswordField` — `TextField` с кнопкой «Показать пароль».
- `Dialog` — модальное окно на `<dialog>`: приподнятая поверхность, крупное
  скругление, тень `lift`, затемнение фона. Стекло не используется.
- `Menu` — выпадающее меню: кнопка-триггер, пункты, закрытие по Escape и клику
  вне меню, стрелки между пунктами.
- Все четыре — на `/design` и в `docs/design-system.md`.

## 9. Задел на подтверждение и восстановление

- `services/otp.py` — 6-значный код, в Redis его хеш, срок 10 минут, повторная
  выдача не чаще раза в 60 секунд, 5 попыток, код одноразовый. Назначения
  `email_verify` и `password_reset`.
- `services/mailer.py` — интерфейс `EmailSender` и `ConsoleEmailSender`, пишущий
  письмо в лог.
- `revoke_all_sessions(user_id)` в сервисе сессий.

## 10. Тесты

Бэкенд работает с настоящими Postgres и Redis (тестовые базы):

- `test_api_auth.py` — регистрация, `me`, обновление, повтор старого
  refresh-токена отзывает сессию, выход; неверный пароль, 409, 422, 429;
- `test_guest_merge.py` — перенос при регистрации, вопрос при входе, merge и
  discard;
- `test_otp.py` — выдача, неверный код, лимит попыток, одноразовость;
- `test_api_reviews.py` — гостю 401, имя автора;
- остальные тесты — под гостем или пользователем вместо `local`.

Фронтенд: формы входа и регистрации, шапка в обоих состояниях, вкладка отзывов у
гостя, диалог переноса, новые компоненты в `ui.test.tsx`.

## 11. Не входит

- Эндпоинты и экраны подтверждения почты и восстановления пароля.
- Профиль, смена имени, почты и пароля, удаление аккаунта, вход через сторонние
  сервисы.
- Список активных сессий в интерфейсе, чистка брошенных гостевых данных.
