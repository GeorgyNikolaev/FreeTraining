# FreeTraining v1.0 — дизайн-документ

Дата: 2026-09-12
Статус: утверждён, готов к планированию реализации

## 1. Назначение

Личная платформа для обучения по курсам, созданным ИИ. Владелец платформы
одновременно её единственный пользователь и автор курсов. Платформа решает две
задачи: пройти новую тему с проверкой усвоения и быстро освежить пройденное.

Ключевое ограничение проекта: всё бесплатно. Ни один сценарий версии 1.0 не
требует платных сервисов, ключей доступа и внешних вызовов.

## 2. Границы версии 1.0

Входит:

- Каталог курсов, читаемый с диска.
- Иерархия «курс → модули → уроки», уроки в Markdown.
- Тест после каждого модуля и финальный экзамен курса, оба с выбором вариантов.
- Повторное прохождение тестов с сохранением истории попыток.
- Шпаргалка и глоссарий как отдельные страницы курса.
- Сохранение прогресса и возврат к месту, на котором остановился.
- Дизайн-система: токены, компоненты, живой каталог, свод правил.
- Светлая и тёмная темы с переключателем.

Не входит и перенесено в следующие версии:

- Тест после отдельного урока. Уроки короткие, проверка на уровне модуля достаточна.
- Регистрация и аккаунты. Поле пользователя в базе есть с первого дня и заполнено
  значением `local`, поэтому появление аккаунтов не потребует менять схему.
- Экзамен со свободным текстовым ответом и разбором через языковую модель.
- Поиск по курсам и урокам. Осмыслен при большом числе курсов, на старте бесполезен.
- Создание курса через интерфейс платформы.
- Развёртывание на сервере. Работа только локально.

## 3. Способ создания курсов

Курс — папка с файлами заданной структуры. Интерфейса создания курсов нет и в
ближайших версиях не планируется. Папку может положить кто угодно: Claude Code,
локальная модель в LM Studio, либо автор вручную.

Такое решение убирает из версии 1.0 всю подсистему генерации, снимает вопрос
ключей доступа и стоимости, даёт версионирование курсов через git и возможность
править содержимое обычным текстовым редактором.

## 4. Формат курса на диске

### 4.1 Структура каталогов

```
content/
  python-basics/                    имя папки — идентификатор курса
    course.yaml                     метаданные курса, обязателен
    cheatsheet.md                   шпаргалка, необязателен
    glossary.md                     термины, необязателен
    exam.yaml                       финальный экзамен, необязателен
    01-introduction/                модуль, числовой префикс задаёт порядок
      module.yaml
      01-what-is-python.md          урок, числовой префикс задаёт порядок
      02-installation.md
      quiz.yaml                     тест модуля
    02-syntax/
      module.yaml
      01-variables.md
      quiz.yaml
```

### 4.2 Правила, снимающие ручную работу

1. Идентификаторы берутся из имён папок и файлов и внутри файлов не дублируются.
2. Порядок модулей и уроков определяется числовым префиксом имени.
3. Отображаемое название урока — первый заголовок уровня 1 внутри самого Markdown.

Имена папок и файлов латиницей: они попадают в адрес страницы. Все отображаемые
названия задаются в содержимом и пишутся по-русски.

Источники названий:

| Сущность | Источник названия |
| --- | --- |
| Курс | `course.yaml`, поле `title` |
| Модуль | `module.yaml`, поле `title` |
| Урок | первый заголовок `#` внутри `.md` |

Если в уроке нет заголовка первого уровня, подставляется имя файла без префикса,
а на странице состояния появляется предупреждение.

### 4.3 Формат файлов

`course.yaml`:

```yaml
title: Основы Python
description: Синтаксис, типы данных и функции с нуля.
tags: [python, backend]
level: beginner        # beginner | intermediate | advanced
```

`module.yaml`:

```yaml
title: Введение
```

`quiz.yaml` и `exam.yaml` используют один формат и один движок:

```yaml
pass_score: 70
questions:
  - question: Что выведет `print(2 ** 3)`?
    options: ["6", "8", "9"]
    answer: "8"
    explanation: "** — возведение в степень, а не умножение."

  - question: Какие типы изменяемые?
    options: ["list", "tuple", "dict", "str"]
    answer: ["list", "dict"]
    explanation: "Кортежи и строки неизменяемы."
```

Тип вопроса не указывается: список в поле `answer` означает вопрос с несколькими
правильными ответами, одиночное значение — с одним. Ответ записывается текстом
варианта, а не его номером, потому что так его удобнее писать и проверять глазами.

### 4.4 Валидация

Содержимое разбирается моделями pydantic. Проверяется: наличие названия курса,
наличие хотя бы одного урока в модуле, присутствие значения `answer` среди
вариантов, отсутствие повторяющихся вариантов, диапазон `pass_score` от 0 до 100.

Ошибка в одном курсе не роняет приложение: неисправный курс не попадает в каталог,
а на странице `/health` выводится сообщение с точным указанием места, например
`python-basics / 02-syntax / quiz.yaml: вопрос 3 — ответ "9" отсутствует среди вариантов`.

## 5. База данных

Используется PostgreSQL в контейнере Docker. В базе хранится только то, что
порождает пользователь. Содержимое курсов в базу не дублируется и всегда читается
с диска, поэтому курс можно переписать или перегенерировать, не затрагивая базу.

Связь с содержимым — через строковые идентификаторы, без внешних ключей. Это
осознанная замена системе миграций на старте: схема из трёх таблиц стабильна.
Alembic не подключается.

### 5.1 Таблицы

`lesson_progress` — отметка о пройденном уроке.

| Колонка | Назначение |
| --- | --- |
| `id` | первичный ключ |
| `user_id` | в версии 1.0 всегда `local` |
| `course_id`, `module_id`, `lesson_id` | имена папок и файла |
| `completed_at` | время первого прохождения |

Уникальность по четырём идентификаторам, индекс по паре пользователь-курс. При
повторном открытии урока время первого прохождения не перезаписывается.

`quiz_attempt` — результат попытки теста.

| Колонка | Назначение |
| --- | --- |
| `id` | первичный ключ |
| `user_id`, `course_id` | принадлежность |
| `scope` | `module` или `exam` |
| `module_id` | пусто для финального экзамена |
| `total_questions`, `correct_count`, `score_percent`, `passed` | итог попытки |
| `answers` | JSONB, полный разбор попытки |
| `created_at` | время попытки |

Попытки накапливаются, а не перезаписываются: «пройти заново» создаёт новую
запись. Отсюда получаются история попыток, лучший результат и динамика во времени.
Модуль считается сданным, если хотя бы одна попытка набрала проходной балл.

В поле `answers` сохраняется снимок вопроса целиком: текст вопроса, варианты,
выбранный ответ, правильный ответ и пояснение. Хранение номеров вопросов
недопустимо, поскольку тесты будут перегенерироваться, и разбор старых попыток
превратился бы в бессмыслицу.

`last_position` — место, на котором пользователь остановился.

| Колонка | Назначение |
| --- | --- |
| `id` | первичный ключ |
| `user_id`, `course_id` | уникальны в паре |
| `module_id`, `lesson_id` | последний открытый урок |
| `updated_at` | время последнего захода |

Хранится отдельно от отметок о прохождении, поскольку «где я остановился» и «что я
дочитал» — разные вещи: урок чаще всего бросают недочитанным. Позиция прокрутки
внутри урока не сохраняется.

Все отметки времени хранятся с часовым поясом в UTC. Таблицы создаются при старте
приложения.

### 5.2 Вычисляемые величины

Не хранятся и рассчитываются при запросе: процент прохождения курса, статус курса,
число оставшихся уроков. Курс считается пройденным, когда пройдены все уроки,
сданы тесты всех модулей и сдан финальный экзамен, если он есть.

### 5.3 Известное ограничение

Незавершённая попытка теста не сохраняется: тест проходится за один заход, и при
закрытии вкладки в середине попытка теряется. Хранение черновиков попыток заметно
усложняет систему ради ситуации, которая при десяти вопросах почти не возникает.
Схема готова к такому расширению, если оно потребуется.

## 6. API

Определяющий принцип: правильные ответы не покидают сервер до отправки попытки.
Вопросы отдаются без разгадки, проверку выполняет бэкенд, разбор возвращается в
ответе на отправку.

### 6.1 Чтение содержимого

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/courses` | Каталог: название, описание, теги, уровень, число модулей и уроков, процент прохождения, статус |
| `GET /api/courses/{course}` | Дерево курса, отметки пройденного, наличие шпаргалки, глоссария и экзамена, позиция возврата |
| `GET /api/courses/{course}/lessons/{module}/{lesson}` | Название и текст урока, ссылки на предыдущий и следующий |
| `GET /api/courses/{course}/pages/{page}` | Шпаргалка или глоссарий |
| `GET /api/courses/{course}/quizzes/{module}` | Вопросы теста модуля без правильных ответов |
| `GET /api/courses/{course}/exam` | Финальный экзамен, тот же формат |
| `GET /api/health/content` | Ошибки разбора курсов |

### 6.2 Запись прогресса

| Метод и путь | Назначение |
| --- | --- |
| `POST /api/progress/lessons/{course}/{module}/{lesson}` | Отметить урок пройденным |
| `PUT /api/progress/position/{course}` | Запомнить место остановки |
| `POST /api/quizzes/submit` | Отправить ответы, получить результат и разбор |
| `GET /api/progress/attempts/{course}` | История попыток по курсу |
| `DELETE /api/progress/courses/{course}` | Сбросить прогресс курса |
| `GET /api/progress/export` | Выгрузить весь прогресс в JSON |

Отправка теста — единственный содержательный расчёт в системе: сервер сверяет
ответы с файлом на диске, считает процент, сравнивает с проходным баллом,
сохраняет попытку и возвращает результат с пояснениями по каждому вопросу.
Фронтенд ничего не вычисляет.

Типы TypeScript порождаются из схемы OpenAPI, которую публикует FastAPI, поэтому
описания данных не дублируются вручную, а расхождение обнаруживает компилятор.

## 7. Фронтенд

### 7.1 Экраны

| Адрес | Экран |
| --- | --- |
| `/` | Главная: продолжение обучения и каталог курсов |
| `/courses/:course` | Обзор курса: прогресс, дерево модулей, экзамен, шпаргалка |
| `/courses/:course/:module/:lesson` | Урок |
| `/courses/:course/:module/quiz` | Тест модуля |
| `/courses/:course/exam` | Финальный экзамен |
| `/courses/:course/results` | История попыток с разбором |
| `/design` | Живой каталог дизайн-системы |
| `/health` | Ошибки в файлах курсов |

### 7.2 Возврат к месту остановки

Сохранённая позиция проявляется в трёх местах: блок «Продолжить обучение» на
главной, подпись главной кнопки на карточке курса в каталоге, кнопка возврата и
подсветка урока на странице курса. При отсутствии записи кнопка предлагает начать
курс, при полностью пройденном курсе — повторить его.

### 7.3 Раскладка урока

Две колонки: слева закреплённая навигация по курсу, справа текст ограниченной
ширины. Внизу урока одна главная кнопка, которая одновременно отмечает урок
пройденным и переводит к следующему; после последнего урока модуля она предлагает
пройти тест модуля. На узком экране навигация убирается в выдвижную панель.

### 7.4 Прохождение теста

Все вопросы выводятся одним списком, внизу кнопка проверки. После проверки
структура страницы не меняется: варианты окрашиваются, под каждым вопросом
появляется пояснение, сверху выводится результат и кнопка повторного прохождения.
Один компонент обслуживает и тесты модулей, и финальный экзамен.

### 7.5 Организация кода и состояние

```
frontend/src/
  pages/          экраны
  features/quiz/  прохождение и разбор теста
  components/ui/  дизайн-система
  lib/api/        клиент и типы, порождённые из схемы бэкенда
  styles/tokens.css
```

Серверными данными управляет TanStack Query: кеширование, состояния загрузки и
ошибок, обновление зависимых экранов после записи прогресса. Собственного
состояния почти нет: локально хранятся только выбранные варианты в текущем тесте
и выбранная тема оформления.

## 8. Дизайн-система

Визуальное направление: нейтральная современная основа в духе shadcn/ui с
заимствованиями из оформления macOS и iOS — крупные скругления, полупрозрачные
слои с размытием, мягкая глубина вместо жёстких границ. Акцентный цвет
изумрудный. Обе темы с переключателем. Просторная типографика.

### 8.1 Размещение

1. `frontend/src/styles/tokens.css` — все значения, единственное место с конкретными цветами и размерами.
2. `frontend/src/components/ui/` — компоненты, собранные только из токенов.
3. Страница `/design` — живой каталог токенов и компонентов во всех состояниях.
4. `docs/design-system.md` — правила словами, справочник для человека и для ИИ.

### 8.2 Токены

Два слоя. Примитивы задают палитру, смысловые токены задают роли: поверхность,
приподнятая поверхность, текст, приглушённый текст, граница, акцент, успех,
ошибка, кольцо фокуса. Компоненты обращаются только к смысловым токенам, поэтому
тёмная тема переопределяет второй слой, не затрагивая компоненты, а смена
акцентного цвета сводится к правке двух строк.

Типографика: системный шрифт Apple с запасным Inter, моноширинный SF Mono. Шкала
12, 14, 16, 18, 20, 24, 30, 36. Текст урока 18 пикселей, межстрочный интервал 1.7,
ширина строки около 68 символов.

Пространство: шкала, кратная четырём — 4, 8, 12, 16, 24, 32, 48, 64.
Промежуточных значений не существует.

Скругления: 10 у кнопок, 14 у карточек, 20 у крупных панелей. Глубина в светлой
теме — мягкими многослойными тенями, в тёмной — светлой границей сверху, поскольку
тени там не читаются.

Стекло: отдельные токены фона, размытия и границы. Применяется строго к шапке,
боковой навигации урока и выдвижной панели. Под текстом урока стекло не
используется никогда, поскольку размытие ухудшает читаемость длинного текста. При
отсутствии поддержки размытия подставляется плотный фон.

Движение: 150 миллисекунд для состояний элементов, 250 для панелей, мягкое
пружинное появление всплывающих слоёв. Системный режим уменьшенной анимации
отключает переходы.

### 8.3 Правила

1. В компонентах не встречаются конкретные цвета и размеры, только смысловые токены.
2. Любой отступ берётся из шкалы, кратной четырём.
3. На экране одно акцентное действие, остальные кнопки вторичные.
4. Стекло применяется только к шапке и навигации, не под содержимым.
5. Иерархия строится размером и насыщенностью текста, а не рамками и заливками.
6. У каждого интерактивного элемента описаны наведение, фокус с клавиатуры, нажатие и заблокированное состояние.
7. Контраст текста не ниже 4.5:1 в обеих темах.
8. Перед созданием нового компонента проверяется наличие подходящего в каталоге компонентов.

Отдельное правило по цвету: изумрудный служит и акцентом, и признаком правильного
ответа. Внутри теста акцентные кнопки не используются, поэтому зелёный там
читается однозначно как «верно», а неверный ответ обозначается красным.

### 8.4 Состав компонентов версии 1.0

`Button`, `Card`, `Badge`, `ProgressBar`, `ProgressRing`, `GlassPanel`, `Tabs`,
`ModuleTree`, `AnswerOption`, `ResultBanner`, `Callout`, `Breadcrumbs`,
`EmptyState`, `Skeleton`, `ThemeToggle`. Иконки — `lucide-react`. Оформление
Markdown вынесено в отдельный слой, настроенный теми же токенами.

## 9. Технологический стек

| Слой | Технология |
| --- | --- |
| Бэкенд | Python 3.12, FastAPI, Pydantic v2, Uvicorn |
| Доступ к базе | SQLModel поверх SQLAlchemy, драйвер asyncpg |
| База данных | PostgreSQL в контейнере Docker |
| Содержимое | Папки на диске, Markdown и YAML, читает бэкенд |
| Фронтенд | Vite, React, TypeScript, React Router, TanStack Query, Tailwind CSS |
| Отображение уроков | react-markdown, remark-gfm, подсветка кода |
| Запуск | docker compose для базы, отдельные процессы бэкенда и фронтенда |

Обоснование выбора. Бэкенд на Python выбран с прицелом на будущий разбор
развёрнутых ответов языковой моделью — соответствующий инструментарий живёт в
Python, а pydantic заодно даёт понятную проверку структуры курсов. Серверный
рендеринг во фронтенде не нужен, поскольку сервером выступает FastAPI, поэтому
фронтенд — обычное одностраничное приложение. Содержимое курсов не попадает в
сборку фронтенда: его отдаёт бэкенд, поэтому новый курс появляется после
обновления страницы, без пересборки.

## 10. Критерии готовности версии 1.0

1. Новый курс появляется в каталоге после создания папки и обновления страницы, без перезапуска и пересборки.
2. Ошибка в файлах курса не ломает приложение и выводится понятным текстом на странице состояния.
3. Курс проходится от начала до конца одной главной кнопкой на каждом экране.
4. Прогресс переживает перезапуск приложения и перезагрузку браузера.
5. Главная предлагает продолжить с того урока, на котором пользователь остановился.
6. Тест модуля и экзамен проходятся повторно, все попытки сохраняются и доступны для разбора.
7. Правильные ответы недоступны в сетевых запросах до отправки попытки.
8. Обе темы переключаются, и ни один экран не теряет читаемость.
9. Страница каталога дизайн-системы отображает все токены и компоненты.
10. Прогресс выгружается в JSON одной кнопкой.
